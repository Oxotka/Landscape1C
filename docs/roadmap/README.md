# Роадмап обучения 1С — заготовка и анализ данных

> Статус (15.06.2026): **исследование, не реализация.** Здесь зафиксировано всё, что нужно,
> чтобы позже вернуться и собрать роадмап обучения, опираясь на данные этого каталога.
> Сам роадмап планируется **отдельной задачей / отдельным репозиторием**; этот проект
> (`Landscape1C`) выступает только **поставщиком данных об инструментах**.

## Замысел и границы

- Роадмап = «что за чем учить» для специалиста 1С.
- **Стартуем только с роли «разработчик».** Аналитик/админ — позже отдельными этапами.
- Гранулярность разметки — **по субкатегориям, не по каждому инструменту.**
  Объём реальный: **60 пар категория/субкатегория всего, 48 затрагивают разработчика** (не 220 карточек).
- Роадмап живёт в новом репозитории; каталог отдаёт ему инструменты + минимум новых полей.

## Ключевой вывод (рамка)

Каталог — это база **инструментов**. А «что за чем учить» — это в первую очередь про
**навыки/темы платформы** (запросы, регистры, RLS, СКД, клиент-серверное взаимодействие…),
которых у нас как карточек **нет и быть не должно** (см. `../competencies/coverage.md`:
«RLS, клиент-серверное — навык платформы, инструмента нет»).

Поэтому роадмап = **скелет тем + порядок** (новый, в отдельном репо)
**+ наши инструменты, подвешенные к темам**.

«Не хватает данных» делится на две кучи:

- **A. Добор в каталоге** (мало, по субкатегориям) — см. ниже.
- **B. Скелет тем и порядок** — рождается в новом репо из внешних источников (УЦ1, Infostart, матрицы компетенций).

## Что уже есть в каталоге (снимок исследования)

Числа ниже относятся к исходному исследованию, а не к текущему каталогу. На
05.09.2026 в `app/data.js` — 229 карточек, 24 категории и 6 блоков; актуальный
этап проекта — опрос 2026 (см. [`../TZ.md`](../TZ.md)). Учебный роадмап остаётся
отдельным исследованием.

- 220 узлов-инструментов с богатыми метаданными.
- Иерархия **блок → категория → подкатегория**.
- Ось «уровень» — **шкала зрелости** (`базовое` 20 / `продвинутое` 75 / `нишевое` 125). Грубый порядок «что раньше».
- **Развилки «выбери один из»** — `analogs` у 81% карточек (178/220).
- **Направленные рёбра** — `depends` (105 связей, 36% карточек). ВНИМАНИЕ: это **техническая/рантайм** зависимость (стек запуска), НЕ учебный порядок.
- Поле **`start`** — ссылки «с чего начать» у 179/220 карточек (= ресурсы узла).
- **Категория «Сертификация»** — формальная лестница экзаменов (см. ниже). Наш козырь против roadmap.sh.
- Страница **«Путь»** (`app/path.js`) уже строит роадмап-подобное: роль × ступень-зрелости × блок + прогресс «знаю» (localStorage `pathKnown`).

## A. Чего не хватает в каталоге (добор по субкатегориям)

| Чего не хватает | Сейчас | Что сделать |
|---|---|---|
| **Уровень субкатегории** (на каком грейде входит) | зрелость стоит на инструменте, у группы своего уровня нет | разметить 48 групп Junior/Middle/Senior — или грубо агрегировать из зрелости инструментов |
| **Учебный пререквизит между субкатегориями** («VCS → потом CI/CD») | `depends` не годится (технический, межинструментный) | десятки рёбер на уровне групп |
| **Входной инструмент группы** (что брать первым) | частично: `start` + `analogs` | флаг «дефолт» или выводить из `базовое` > зрелость |
| **must / рекомендуется** на узле | нет | расконсервировать **только** срез `v`/`ж` из грейд-матриц (см. competencies) |
| **Привязка к экзаменам** | есть категория «Сертификация», но связей нет | ребро «тема/инструмент → экзамен» |

### Категория «Сертификация» (готовые вехи / milestones)

- 1С:Профессионал — базовый экзамен на знание платформы и типовых конфигураций
- 1С:Специалист-консультант — внедрение и сопровождение прикладных решений
- 1С:Специалист — решение практических задач в конфигурациях
- 1С:Эксперт по технологическим вопросам — оптимизация и нестандартные технические решения
- 1С:Эксплуататор — настройка и поддержка крупных систем
- Сертификация от 1С-ТестЦентр; Сертификация от Госуслуг

Лестница **1С:Профессионал → 1С:Специалист → 1С:Эксперт** — естественный backbone прогресса,
которого у Python-роадмапов нет.

## B. Что подсмотреть у roadmap.sh / Python (структуру, не контент)

Шаблон полей на узел ложится на нас один-в-один:

- **type:** topic / subtopic / tool / label(«порядок не строгий») — `tool` у нас есть, `topic` надо завести.
- **recommendation:** recommended / alternative / optional — это и есть must/nice (грейды) + `analogs` (alternative).
- **resources (free/paid)** — у нас это `start`.
- **backbone + branches:** у Python «основы языка → инструменты → специализация (web/data/devops)».
  У нас **backbone = платформа 1С** (язык → объекты → запросы → СКД), **branches = роли/контексты**.

Чего у Python **есть, а у нас нет** — сами темы-навыки как узлы (завести в новом репо).
Чего у нас **есть, а у Python нет** — лестница экзаменов и готовый каталог инструментов с альтернативами и уровнем.

## Связь с веткой `feature/competencies` (грейды)

- Слой грейдов **заморожен**: для одной роли грейд ≈ шкала зрелости (меры одного и того же). См. `../competencies/README.md`.
- Для роадмапа это **в плюс**: ось «уровень» уже есть бесплатно через зрелость, отдельные грейды не нужны.
- Что из той ветки реально нужно роадмапу:
  - срез **must / nice-to-have** (`v`/`ж` из листа «Программисты») — единственное, что стоит расконсервировать;
  - **`coverage.md`** — расшифрованный маппинг «компетенция/навык → инструменты ландшафта» (готовый скелет дорожек для разработчика);
  - расшифрованные матрицы компетенций (`docs/competencies/sources/`).

## Следующий шаг (когда вернёмся)

1. Решить формат полей в `data.js` (по аналогии с осями): уровень субкатегории + учебный пререквизит + (опц.) флаг «вход в группу» + must/nice + связь с «Сертификацией».
2. Завести модель тем-навыков платформы в новом репо (источники — УЦ1/Infostart/матрицы).
3. Собрать дорожки для разработчика: backbone (платформа+экзамены) + ветки (контексты), инструменты из каталога подвешиваются к темам.
