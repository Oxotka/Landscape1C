# Черновик разметки «инструмент → грейд» (роль: разработчик)

> Быстрый поверхностный первый проход (вариант C). Спорные места согласованы (см. историю ниже).
> Шкала: **J** = Junior, **M** = Middle, **S** = Senior, **S+** = Senior+.
> Грейд = минимальный уровень, с которого инструмент реально нужен/осваивается.

## Главный принцип: размечаем по КАТЕГОРИЯМ, не по карточкам

Инструменты уже сгруппированы по ~30 категориям, и категория почти всегда соответствует **одной компетенции** из матриц. Базовая разметка — ~30 решений «категория → грейд», дальше точечно правим единичные карточки-исключения. Разметки 137 карточек по одной **не требуется**.

## ⚠️ Грейд зависит от РОЛИ (ключевое уточнение)

Один и тот же инструмент может иметь **разный грейд для разных ролей**: что для крутого разработчика — продвинутый навык, для среднего администратора — база. Пример: сетевая инфраструктура (Apache/IIS) — для разработчика это Middle+, для администратора Junior. Аналогично диаграммы: для аналитика — Junior, для разработчика — Middle.

**Следствие для модели данных:** грейд храним **в разрезе роли**, например:

```js
"grade": { "разработчик": "middle", "администратор": "junior" }
```

- Сейчас заполняем **только `разработчик`** (стартуем с него).
- Нет ключа для роли → в «Пути» этой роли инструмент по грейдам не раскладывается.
- Расширяемо: дойдём до админа/аналитика — допишем их ключи по их матрицам.

Все грейды ниже — **для роли «разработчик»**.

## Разметка по категориям (роль: разработчик)

| Блок | Категория | Грейд | Примечание / исключения |
|---|---|---|---|
| Проектирование | Прототипирование | **S** | — |
| Проектирование | Диаграммы | **M** | для коммуникации; у аналитика было бы раньше |
| Проектирование | Моделирование и архитектура | **S** | проектирование системы |
| Проектирование | База знаний | **J** | нужен сразу |
| Разработка | Разработка | **J** | **искл.:** EDT → **S**, VSCode → **M**, Элемент/Элемент Скрипт → **S+**, OneScript → **M** |
| Разработка | Библиотеки и инструменты | **J** | **искл.:** Infostart Toolkit, подсистемы инструментов → **M**; Autumn → **S+** |
| Разработка | Плагины и расширения | = родитель | грейд плагина = грейд его инструмента (плагины EDT → S, VSCode → M, конфигуратора → J) |
| Разработка | ИИ-ассистенты | **M** | вне матриц (2025), отнесли к Middle — повышают продуктивность уверенного разработчика |
| Разработка | Системы хранения версий | **J** | git/хранилище — must с Junior |
| Разработка | CI/CD | **S** | nice-to-have c Senior |
| Качество | Автоматизированное тестирование | **S** | простые сценарии — с J/M; фреймворки — S |
| Качество | Статический анализ кода | **M** | Синтаксическая проверка, Стандарты разработки → **J** |
| Качество | Код-ревью | **S** | must с Senior |
| Инфраструктура | Сетевая инфраструктура и облако | **M** | у администратора было бы **J** (см. per-role) |
| Инфраструктура | Безопасность | **M** | у администратора было бы **J** |
| Инфраструктура | СУБД | **S** | Файловая СУБД → **J** |
| Инфраструктура | Мониторинг | **S+** | ниша/эксперт |
| Инфраструктура | Производительность и нагруз. тест. | **S** | — |
| Данные/интеграции | Интеграции | **M** | 1С:Шина, Kafka, RabbitMQ, S3 → **S** |
| Данные/интеграции | API и веб-сервисы | **M** | — |
| Управление | Задачи (трекеры) | **J** | сквозной рабочий инструмент, нужен сразу |
| Управление | Сертификация | спец. | 1С:Профессионал → **J**, 1С:Специалист → **M/S**, 1С:Эксперт → **S+** |

> «Сертификация» ложится прямо на грейды — независимое подтверждение, что шкала разумная.

## Решённые ранее сомнения

1. **ИИ-ассистенты** → **Middle** (вне матриц, отнесли вручную). ✓
2. **База знаний** → **Junior** (нужен сразу). ✓
3. **Плагины и расширения** → грейд родительского инструмента. ✓
4. **Инфраструктура/Безопасность** → грейд **зависит от роли** → ввели per-role модель (выше). Для разработчика — Middle. ✓
5. **Диаграммы** → Middle; **Проектирование/моделирование** → Senior. ✓
6. **Трекеры задач** → **Junior** (как база знаний). ✓

## Остался один микровопрос

«Junior» vs «без грейда» для **сквозных** инструментов (база знаний, трекеры). Сейчас стоит **Junior** — это технически удобнее: в «Пути» ступени = грейды, инструменту «без грейда» некуда лечь. Семантически Junior здесь = «нужно сразу, всем». Если хочется явного значения «вне грейдов» — это отдельная зона в UI (усложнение). **Рекомендация: оставить Junior.**
