# Базовый стек разработчика 1С в 2026 году: Конфигуратора больше недостаточно

Конфигуратор больше не базовый стек разработчика 1С. Это одна программа из стека.

Рядом с ним уже стоят git, Visual Studio Code, API-клиент, статический анализ и, внезапно, Docker.

В текущем опросе Ландшафта технологий 1С с VS Code работали 84% ответивших, с git 76%, с Postman 68%. Docker использовали 57%, SonarQube 55%. Это слишком много, чтобы продолжать называть их игрушками энтузиастов.

Мой тезис простой: **разработчик 1С в 2026 году должен понимать весь путь кода от Конфигуратора до репозитория, автоматической проверки и рабочего окружения**.

Не обязательно самому поднимать SonarQube и писать Dockerfile с закрытыми глазами. Но впервые узнавать о контейнерах, статическом анализе и модели git на собеседовании уже неприлично.

Вот что сегодня относится к базовому стеку:

- **код:** Конфигуратор, 1C:EDT, Visual Studio Code, BSL Language Server;
- **прикладная разработка:** БСП, консоль запросов, стандарты разработки, подсистема «Инструменты разработчика»;
- **версии:** Хранилище конфигурации, git и GitHub либо GitLab;
- **интеграции:** Postman или другой API-клиент;
- **среда и качество:** Docker, SonarQube и BSL Community Plugin.

Список намеренно широкий. Профессия тоже стала шире. Граница между «обычной разработкой 1С» и «каким-то вашим DevOps» давно переехала, просто не все обновили карту.

## Классические инструменты остаются

Конфигуратор остаётся точкой входа. Его даже не включали в текущую волну: спрашивать специалиста 1С, слышал ли он о Конфигураторе, было бы издевательством над анкетой.

Классические инструменты оценивали на июльском этапе:


| Инструмент                       | Работали   | Выбрали бы снова |
| -------------------------------- | ----------: | ----------------: |
| Библиотека стандартных подсистем | 99% из 207 | 99% из 202       |
| Консоль запросов                 | 97% из 242 | 98% из 230       |
| Хранилище конфигурации           | 94% из 209 | 69% из 193       |
| Стандарты разработки 1С          | 92% из 203 | 99% из 184       |


БСП, консоль запросов и стандарты разработки — железная база. А вот Хранилище попало в неловкое положение: с ним работали почти все, но повторить выбор готовы лишь 69%.

Массовость Хранилища говорит о прошлом и настоящем. Желание вернуться к нему о будущем. И будущее у него выглядит заметно хуже, чем статистика использования.

## Git победил, но хранилище ещё не заметило

С git работали 76% из 206 ответивших. На вопрос о повторном выборе ответили 152 человека. Все 152 выбрали бы git снова. Все сто процентов.

У GitHub 81% использования и 99% повторного выбора. GitLab использовали 64% ответивших, 98% готовы выбрать его снова. Конкретный хостинг можно обсуждать, но git уже нельзя складывать в папку «продвинутое, изучу потом».

Хранилище завтра не исчезнет. Команды ещё долго будут жить сразу в двух мирах. Но один мир держится на огромной установленной базе, а из второго никто не хочет возвращаться.

## VS Code — уже инструмент разработчика 1С

С Visual Studio Code работали 84% из 208 ответивших. Повторно его выбрали бы 97%. Это уже не запасной блокнот для JSON.

Вокруг него выросла своя 1С-экосистема. BSL Language Server использовали 68% из 191.  Повторный выбор  99%.

Конфигуратор остаётся на месте, но проект 1С давно не ограничивается только информационной базой. Исходники, скрипты, документация, настройки и пайплайны тоже требуют рабочего инструмента. Поэтому современный разработчик 1С живёт сразу в нескольких редакторах.

С EDT успели поработать 69% из 185 ответивших, а слышали о нём почти все 99%. Снова выбрали бы EDT те же 69%. Инструмент уже прочно вошёл в рабочий набор специалистов 1С, но любимым пока не стал.

## Postman оказался инструментом 1Сника. Смиритесь

Postman использовали 68% из 240 ответивших. Повторно его выбрали бы 94%.

Я ожидал число гораздо ниже. Видимо, образ разработчика 1С, который никогда не выходит из платформы, пора сдавать в архив вместе с дисками ИТС.

HTTP-сервисы, REST API, вебхуки и обмены стали обычной частью работы. Сам Postman можно заменить на Bruno, Insomnia, curl или встроенные средства, но умение отправить запрос, проверить авторизацию, увидеть заголовки и разобрать ответ уже входит в профессию.

Postman здесь просто оказался свидетелем: разработка 1С давно вышла за границы 1С.

## Docker и SonarQube больше не фишка для доклада

- Docker использовали 57% из 204 ответивших;
- SonarQube - 55% из 191;
- SonarQube BSL Community Plugin - 51% из 192.

Повторный выбор — 97%, 98% и 98%.

Больше половины ответивших уже работали с этими инструментами. Почти все попробовавшие готовы выбрать их снова. После таких цифр слово «продвинутые» звучит особенно скромно.

Нет, каждый разработчик не обязан администрировать контейнерную инфраструктуру. Но он должен понимать, зачем команде воспроизводимое окружение, как код попадает в автоматическую проверку и где смотреть найденные проблемы. Это уже профессиональная грамотность, а не факультатив для самых любознательных.

## Откуда цифры

В текущей волне опроса уже ответили 276 специалистов, из них 205 назвали основной ролью разработку. Маршруты вопросов различаются, поэтому процент каждого инструмента считается среди тех, кому его показали и кто ответил. Опрос измеряет опыт работы, а не частоту и глубину владения.

Ещё 13 базовых инструментов оценивали на отдельном июльском этапе с 247 участниками. Поэтому показатели Хранилища и git взяты из разных этапов. Я поставил их рядом как два ярких сигнала, а не как результат прямого сравнительного эксперимента.

Данные показывают опыт участников. Граница базового стека — моя интерпретация. Именно её я и предлагаю разнести в комментариях.
